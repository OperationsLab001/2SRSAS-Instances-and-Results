# 2SRSAS Concrete Benchmark Instance Set

**Release date:** 2025-11-12  
**Format:** NumPy compressed archive (`.npz`)  
**Number of base instances:** 30  
**Classes:** `(3,6,12,20)`, `(5,10,24,40)`, `(8,15,24,60)` with ten base instances in each class.

## 1\. Scope and provenance

This release provides concrete Python-readable benchmark instances for:

**Integrated Staffing and Scheduling for a Multiclass Service System under Arrival-Rate Uncertainty: A Two-Stage Scenario-Based Robust Optimization Approach**

The source documents specify the model parameters, parameter distributions, demand-generation formulas, correlation structure, scenario probabilities, robustness parameters, staffing-bound formulas, emergency-capacity scaling, and training/testing seed mapping.

The source documents also state that the fixed saved instance and demand arrays used in the reported experiments are the reference inputs, and that seeds alone do not uniquely determine a historical random-number implementation or draw order. Therefore, this release should be understood as a **new fully specified concrete benchmark release generated from the documented rules**, not as a byte-for-byte recovery of unavailable historical arrays. Once this archive is used as the released benchmark set, the `.npz` files themselves are the authoritative inputs for this release.

## 4\. Core arrays in every instance

### Sets and dimensions

* `I\_index`: employee-type indices, zero based.
* `J\_index`: customer-class indices, zero based.
* `T\_index`: period indices, zero based.
* Dimensions are also stored in `metadata\_json`.

### Skill compatibility and service parameters

* `compatibility\_A` — shape `(I,J)`, entries 0/1.
* `mu\_service\_rate` — shape `(I,J)`, generated from `U\[0.8,1.5]`.
* `tau\_service\_requirement` — shape `(I,J)`, `1/mu`.
* `rho\_capacity\_factor` — shape `(I,T)`, generated from `U\[0.75,1.00]`.
* `cO\_emergency\_cost` — shape `(I,T)`, generated from `U\[20,40]`.
* `pA\_abandonment\_penalty` — shape `(J,)`, generated from `U\[80,150]`.
* `pR\_backlog\_penalty` — shape `(J,)`, generated from `U\[10,30]`.

The baseline compatibility matrix is generated with target probability `phi=0.50`, then repaired in the documented order: first empty customer-class columns, then empty employee-type rows.

### Shift data

Each class contains exactly the documented average number of feasible shifts per employee type (`S=20`, `40`, or `60`). A shift is a consecutive block of 2, 4, 6, or 8 periods.

* `shift\_type` — employee type owning each shift.
* `shift\_local\_id` — shift id within its employee type.
* `shift\_start\_0based` — first covered period.
* `shift\_length` — number of consecutive covered periods.
* `cS\_shift\_cost` — shift-assignment cost, generated from `U\[80,140]`.
* `shift\_coverage` — shape `(number\_of\_shifts,T)`, binary coverage matrix.

For a shift row `s`, `shift\_coverage\[s,t]` is the stored version of `a\_ist`.

### Baseline demand

* `b\_class\_demand\_level` — class-specific level `b\_j \~ U\[4,6]`.
* `h\_time\_profile` — `1 - 0.30\*cos(2\*pi\*(t-0.5)/T)`.
* `lambda0\_baseline\_demand` — shape `(J,T)`, `b\_j\*h\_t`.

### Correlation structure

* `Sigma\_J` — cross-class correlation matrix with off-diagonal correlation `0.30`.
* `Sigma\_T` — temporal AR-like correlation matrix with element `0.60^|t-t'|`.
* `sigma\_lambda = 0.20` is stored in `metadata\_json`.

Nominal scenario demand is generated by

```text
bar\_lambda\[j,t] =
    max(1, round(lambda0\[j,t] \* (1 + 0.20 \* epsilon\[j,t])))
```

with Gaussian perturbations having covariance `Sigma\_J ⊗ Sigma\_T`.

This release uses NumPy `rint` for the documented rounding operation.

## 5\. Scenario sets

For every base instance, four **distinct** training samples are stored:

* `train\_nominal\_Omega8`
* `train\_nominal\_Omega16`
* `train\_nominal\_Omega32`
* `train\_nominal\_Omega64`

They are drawn sequentially from the documented training seed

```text
seed\_train(b) = 2026 + 1000\*b
```

and therefore are not nested prefixes of one 64-scenario array.

Corresponding equal scenario probabilities are stored as:

* `scenario\_probability\_Omega8`
* `scenario\_probability\_Omega16`
* `scenario\_probability\_Omega32`
* `scenario\_probability\_Omega64`

with every probability equal to `1/|Omega|`.

## 6\. Robust uncertainty parameters

The documented deviation factors are

```text
alpha ∈ {0.10, 0.20, 0.30}
```

with baseline `alpha=0.20`.

For every scenario-set size, the archive stores the explicit deviation tensor

```text
hat\_lambda = alpha \* train\_nominal
```

under names such as:

* `hat\_lambda\_alpha010\_Omega32`
* `hat\_lambda\_alpha020\_Omega32`
* `hat\_lambda\_alpha030\_Omega32`

The documented budget factors are

```text
q ∈ {0.10, 0.20, 0.30}
Gamma = floor(q\*J\*T)
```

and the explicit integer budgets are stored under names such as:

* `Gamma\_q010\_Omega32`
* `Gamma\_q020\_Omega32`
* `Gamma\_q030\_Omega32`

For the three classes these equal:

|Class|J\*T|q=0.10|q=0.20|q=0.30|
|-|-:|-:|-:|-:|
|3-6-12-20|72|7|14|21|
|5-10-24-40|240|24|48|72|
|8-15-24-60|360|36|72|108|

## 7\. Staffing bounds and emergency-capacity limits

For each scenario-set size, the file stores:

* `mean\_train\_demand\_OmegaN`
* `bar\_tau\_OmegaN`
* `bar\_rho\_OmegaN`
* `N\_ref\_OmegaN`
* `N\_min\_OmegaN`
* `N\_max\_OmegaN`
* `O\_emergency\_limit\_OmegaN`

The formulas are:

```text
bar\_lambda\[j,t] = mean of nominal scenario demand
bar\_tau\[j]      = average tau\[i,j] over compatible employee types
bar\_rho\[t]      = average rho\[i,t] over employee types

N\_ref = ceil(
    max\_t sum\_j bar\_tau\[j] \* bar\_lambda\[j,t] / bar\_rho\[t]
)

N\_min = ceil(0.8 \* N\_ref)
N\_max = ceil(1.4 \* N\_ref)
```

The baseline emergency-capacity limit is

```text
O\[i,t] =
    0.25 \* sum\_{j compatible with i} tau\[i,j] \* bar\_lambda\[j,t]
```

so `kappa=0.25`.

Because the manuscript explains that changing `|Omega|` may change sample-calibrated DET/RO inputs and physical bounds, these derived arrays are stored separately for each training scenario size.

## 8\. Out-of-sample demand

Each instance stores

* `test\_demand\_1000` — shape `(1000,J,T)`.

It is generated from the same correlated demand process using the independent documented testing seed

```text
seed\_test(b) = 2026 + 1000\*b + 500.
```

The same test set can therefore be used to evaluate DET, SP, RO, and SRO for the base instance.

## 9\. Additional experimental constants

`metadata\_json` records:

* master seed `2026`;
* `sigma\_lambda=0.20`;
* `rho\_T=0.60`;
* `rho\_J=0.30`;
* baseline `phi=0.50`;
* baseline `kappa=0.25`;
* `alpha = {0.10,0.20,0.30}`;
* `q = {0.10,0.20,0.30}`;
* cost-ratio values `chi = {0.50,0.75,1.00,1.25,1.50,2.00}`;
* skill-flexibility sensitivity targets `{0.25,0.40,0.55,0.70,0.85,1.00}`;
* `N\_test=1000`;
* time limit `3600 s`;
* target relative optimality tolerance `1e-4`;
* `epsilon\_score=epsilon\_lazy=1e-5`.

The solver settings are retained as experiment metadata; they are not structural coefficients of the mathematical instance.

## 10\. Units

The files follow the dimensional interpretation in the manuscript:

* demand: customer-demand units arriving in a period;
* `mu`: customer-demand units served per unit of effective working time;
* `tau=1/mu`: effective working time required per unit of demand;
* `rho`: dimensionless effective-capacity factor;
* `O`: effective working-time capacity units.

## 11\. Release-specific RNG convention

The documents give master seed `2026` but do not give the historical random draw order used to produce the saved physical instance arrays. To make this release independently reproducible, physical parameters for base instance `b` use:

```python
np.random.default\_rng(
    np.random.SeedSequence(\[2026, b, 271828])
)
```

This convention is stored in each instance's `metadata\_json`. It is a release-specific deterministic convention, not a claim about an unavailable historical implementation.

Training and testing demand seeds follow the manuscript/supplement exactly.
